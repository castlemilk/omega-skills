Use the master to organise a batch. Send one focused construction brief to each render, with only the relevant output mode. Preserve the exact submitted prompt and actual image inputs.

## Run controls

Resolve the requested number **N** from the current request and any unfinished active batch. Accept positive whole numbers, including unambiguous numbers written in words. Use five only when no explicit or active count exists. Do not treat numbers describing an era or geometry as the batch count, or a quoted shortcut example as an instruction to generate.

Count final separate presentations. Miniatures, rejected attempts and corrections do not increase N. Deliver all N in manageable waves without an arbitrary cap. If a real capability limit blocks completion, identify the completed images and exact remainder.

Use **refinement** when the user identifies a mark to preserve; change only the named properties. Otherwise default to **radical exploration**. In radical batches of at least five, aim for roughly 60% substantially fresh constructions, using the rest for useful comparisons. Do not apply novelty quotas to refinement.

## Master brief

```text
Create original visual identity artwork for "beneb systems".

Focus: [core logos / one extension mode]
Era: year 3000
Mode: [radical exploration / refinement]
Images: [N] separate presentations
Palette: obsidian and near-black with flat ivory geometry
Geometry: clean strong contours, substantial masses, deliberate negative space
Symmetry: [chosen rule, or controlled asymmetry]
Reference roles: [geometry ancestors, presentation references, edit targets, or none]

Imagine an institution engineering intelligence, bodies, materials, habitats
and physical systems for humans and machines. Its identity feels quiet,
exact, authoritative and partially unfamiliar.

Make the future visible in relationships between forms: what connects,
what a boundary changes, what an absence determines and what remains
recognisable across a transformation.

Choose one speculative organising rule and one meaningful visual tension.
Translate both into an observable construction. Use ancient monumentality,
biological packing, cybernetic articulation and algorithmic structure as
abstract sources. Invent original forms.

Use a small vocabulary of strong masses. Give each edge a reason.
Establish a memorable silhouette before adding detail.

For core logos, create one separate landscape presentation per direction:
one large flat ivory emblem on obsidian, a small correctly spelled
lowercase "beneb systems" wordmark, and a small flat duplicate preserving
the parts, openings, cuts and orientation. Keep generous darkness and
comparable type, layout and visual weight across the batch.

Avoid stock space or AI icons, literal historical symbols, equations,
fake microtext, circuit wallpaper, decorative HUDs, repeated stacked
plates, rainbow chrome, excessive glow, weak joins and accidental needles.

Inspect the actual result. Describe achieved geometry and departures from
the plan. Keep user selections distinct from provisional design judgments.
```

Possible premises include a boundary exchanged between solid and void, a displaced part that retains a characteristic profile, an open route preserved through a fold, a repeated unit with one controlled exception, or independent bodies coordinating across a shared interval. Invent other premises when useful. Static geometry does not demonstrate a physical process or mathematical invariance; use a motion concept when the relationship requires multiple states.

## Single image brief

Specify the following before each call:

```text
Use case: logo-brand [adapt for other modes].
Output: one separate presentation.
Brand character: beneb systems; year 3000; quiet institutional authority.
Organising premise: [one sentence].
Visible construction: [the actual relationship to render].
Disconnected filled parts: [count and relative sizes].
Enclosed voids: [count and location].
Open recesses: [entry side, route and blind end; or none].
Connections: [which elements join and at which endpoints].
Outer silhouette: [dominant contour, proportion and terminal shape].
Primary experiment: [one formal change or question].
Invariants: [properties to preserve].
Actual image inputs: [each supplied image and its role; or none].
Presentation: [one mode; fixed layout when comparing geometry].
Exact text: "beneb systems" [plus only explicitly requested text].
Failure to prevent: [one concrete risk].
Generate one image.
```

Describe spatial relationships directly. Use approximate dimensions only when needed. Identify exact edges for alignment and exact endpoints for bridges; “make it more futuristic” is not a construction instruction.

For a new branch, use a new construction. For an edit, inspect and attach the actual target through the supported host mechanism. An ancestor inspected during planning is not an image input unless it was supplied to the generator.

## Targeted correction

```text
Edit the supplied image.
Change only [one observed defect].
The current result shows [visible fact].
The required result is [specific geometry].
Connect [part] to [part] at [named endpoint], if applicable.
Keep the opening at [side] and preserve [other relationships].
Apply the same correction to the miniature.
Preserve remaining silhouette, scale, layout, palette and exact text.
Generate one corrected presentation.
```

Reinspect after editing, including neighbouring contours. Keep the earlier version if the edit is weaker. A correction replaces that direction's selected presentation; preserve meaningful attempts in the run record.

## Extension modes

| Focus | Construction and deliverable |
| --- | --- |
| Pattern | Derive a field from the rule. Vary spacing, density, orientation or state while preserving one relationship. Use a few scale levels. Verify edge continuity separately when seamless tiling is requested. |
| Motion concept | Show a short sequence, such as four states, of one recognisable transformation. Name the invariant. A static storyboard is not a finished animation. One storyboard image counts as one presentation unless the user specifies otherwise. |
| Identity suite | Create distinct related silhouettes for different institutional domains. Share a construction grammar while varying the operation; avoid scaled copies with decorations. |
| Engineered object or material | Translate the rule into the object's shell, cavity, seam, joint or assembly. Give it one legible function and one unfamiliar structural relationship. Derive restrained surfaces and depth from that geometry. |
| Environment | Organise mass, thresholds, passages and human/machine scale through the rule. Keep one spatial hierarchy and a restrained scale cue. |
| Placement and graphic material | Let the emblem's axes, cuts and empty regions guide alignment, cropping and surfaces. Make a specific artefact such as a research cover, interface frame or machine identification plate. |

Generate every requested image through an available authorised image capability. Give each a short name and concise caption explaining the visible idea and promising use. Name provisional leaders with concrete reasons, one meaningful weakness and the next useful comparison.
